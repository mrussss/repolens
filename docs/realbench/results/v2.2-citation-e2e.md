## Reasoning-output truncation boundary

This section records the v2.2 output-budget fix and controlled experiment. The
root document `开发文档.md` remains local-only and is not part of this evidence
commit. The frozen `realbench-v1` dataset and manifest were not modified.

The clean implementation HEAD for the experiments was
`900abcc477ff01ed9fb8080d58f0a23342eea813`. The default production
`MaxOutputTokens` remains `2048`; `REPOLENS_REALBENCH_MAX_OUTPUT_TOKENS` is a
RealBench-only explicit override. The experiments below used a 180-second
Provider timeout so that timeout failures did not obscure the output-budget
boundary; these are not the formal default configuration.

### Run C: 8192 output tokens

- Run ID: `20260921T131126Z-367c961d`
- Command: `REPOLENS_PROVIDER_TIMEOUT_SECONDS=180 REPOLENS_REALBENCH_MAX_OUTPUT_TOKENS=8192 go run ./cmd/realbench run --dataset v1 --case REAL-002 --e2e`
- Preflight: `PASS`
- REAL-002 attempts: 3
- Result: all three attempts timed out in Provider `Generate` at 180 seconds
- Failure classification: `EXTERNAL_INFRA`
- Tool calls/final report: not reached

The 8192 run does not demonstrate a complete Agent result; the Provider did
not return within the explicit timeout. Per the experiment stop rule, the
default is not raised to 8192 and no further budget increase is performed.

The controlled evidence therefore shows: 2048 truncates, 4096 still
truncates, and 8192 is currently blocked by the external Provider timeout.
This is a model/provider compatibility and latency boundary, not a Retrieval,
Ground Truth, Citation ID, or Case-definition change.
