## FINAL-R01: durable execution-start boundary

- Root cause: `ClaimJobs` represented both ownership acquisition and actual handler execution by setting `RUNNING` and incrementing `attempt_count`. After a worker died between claim and dispatch, the reaper could not distinguish a never-started claim from a lost execution and could exhaust the retry budget.
- Fix: claims now establish ownership without consuming an attempt. Immediately before launching any registered job handler, the Worker performs the claim-fenced, idempotent `MarkExecutionStarted` transition, which sets `execution_started=true` and increments `attempt_count` once. The transition requires the current RUNNING worker, token, generation, and live lease. Return and start are mutually exclusive on the durable marker. Job finalizers also require a started claim.
