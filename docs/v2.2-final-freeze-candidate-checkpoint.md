# RepoLens v2.2 final-freeze candidate checkpoint

This checkpoint records a candidate for a later independent, read-only audit.
It does not approve a formal freeze, create a tag or release, or claim that
v2.2 has been released.

## Baseline and changes

- Baseline checkpoint: `08630146827c665f4c8c641201109fb782ea304b`.
- The baseline working tree contained an uncommitted stale-Attempt P3 fix;
  this candidate includes it. A live job lease protects only the matching
  generation, Attempt number, and worker; regression coverage confirms an
  older crashed Attempt is reclaimed while its same-generation retry is leased.
- `TriggerIndex` now accepts a strict single JSON object (with empty-body EOF
  compatibility), rejects malformed, mistyped, unknown-field, non-object, and
  trailing JSON input with HTTP 400 / `INPUT_INVALID`, including case-mismatched
  field names, duplicate fields, and invalid UTF-8. It does so before ref
  resolution or Snapshot/Job creation. Handler tests cover the rejection
  matrix and absence of side effects, plus default and explicit-ref behavior.
- Repository / AnalysisRevision polling retains last-known revisions on
  temporary read failures, retries while a known Revision is `PREPARING`,
  exposes a reload action after an initial failure, backs off to a bounded
  interval, slows while hidden, and prevents overlapping requests or updates
  after unmount. Tests cover `PREPARING → temporary failure → READY`, stopping
  after `READY`, retained state, reload, hidden-page timing, and in-flight
  request coalescing.
- README user flow now centers on preparing/reusing and awaiting an
  `AnalysisRevision`; Snapshot, CodeIndexBuild, and RetrievalBuild are described
  as its internal reproducible lineage. Lower-level APIs remain available for
  compatibility and advanced use.
