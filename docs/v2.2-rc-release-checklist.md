# RepoLens v2.2 RC release checklist

This checklist describes the final v2.2 RC gate. It does not create a GitHub
Release or a `v2.2.0` tag.

## Frozen implementation and production configuration

- Development base commit: `5edc79499f6c2741a80c0f411e9531cdc757f53a`.
- The commit containing this checklist is an RC candidate checkpoint for
  follow-up audit; it is not the final v2.2 release.
- No v2.2 tag or GitHub Release has been created.
- Production defaults: `MaxOutputTokens=4096`, `ReasoningEffort=low`,
  `ResponseFormat=json_object`, `ProviderTimeoutSeconds=60`,
  `ProviderRetryAttempts=0`.
- `DiagnosisRun` stores the frozen generation and provider options; the Agent
  does not reread environment variables after a run starts.
- The RealBench dataset, Ground Truth, manifest, historical artifacts, and
  citation semantics are frozen.

## Required checks

- [ ] `gofmt -l cmd internal tests` has no output.
- [ ] `go vet ./...` passes.
- [ ] `go test ./...` passes.
- [ ] `go test -race ./...` passes.
- [ ] Web dependencies install and the production build passes:
  `cd web && npm ci && npm run build`.
- [ ] Real MySQL integration passes with the repository's canonical test
  command: `REPOLENS_REQUIRE_REAL_INTEGRATION=1 go test -v -race ./tests/integration_real/...`.
- [ ] The MySQL Golden Path passes through `go test -v ./tests/e2e/...`.
- [ ] Docker Compose smoke passes through `./scripts/release_gate.sh`,
  including compose config/build, service health, and the demo trigger.
- [ ] Provider compatibility probe is exercised through
  `POST /settings/provider/test` when an operator has explicitly configured a
  Provider secret. The probe validates the production request shape with a
  small output budget and reports `PROVIDER_CAPABILITY_UNSUPPORTED` only for
  explicit optional-capability rejection or an invalid tool response when a
  tool call is returned; a successful response without a tool call is marked
  inconclusive. Ordinary HTTP failures and probe truncation keep their own
  classifications.
- [ ] No API key, raw Provider response, or sensitive Provider metadata is
  committed or written to logs, traces, or test artifacts.

## Known limitations

- RealBench is a small, non-deterministic model-quality sample rather than a
  production accuracy guarantee. A valid structured report with invalid or
  unknown citations remains `Diagnosis=SUCCEEDED` and
  `ReportStatus=DEGRADED`; the independent citation gate may be `FAILED`.
- Malformed JSON, missing required report fields, and illegal
  `conclusion_kind` are product failures: the report is `INVALID`, Diagnosis
  is `FAILED`, and the Attempt is `FAILED_TERMINAL`; raw output and parse
  error are retained for diagnosis.
- Provider compatibility is about the request/response capability shape, not
  a guarantee of latency, quota, model quality, or broad root-cause accuracy.
- Live Provider compatibility was not run in this RC audit without an explicit
  secret; mock probe tests are not live Provider evidence.
- No formal release/tag is created by this checklist.
